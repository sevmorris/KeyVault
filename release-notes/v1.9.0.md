**Added**
- **Files: whole files, stored encrypted in the vault.** A password manager's CSV export, a service-account key, a recovery kit — anything up to 25 MB. Use Add File… (⌥⌘N), the toolbar or the + under the Files list, or drop a file on the list. Each file is encrypted with your master passphrase before it is written, and kept in KeyVault's own folder rather than the Keychain. Its name and notes are encrypted with it, so nothing about a stored file is readable without the passphrase — not even what it is called. Files can be stored only once a master passphrase is set.
- **The original can go to the Trash once the file is stored.** On by default, and done only after the stored copy has been read back. The Trash keeps it readable until the Trash is emptied.
- **Text files show on the screen, and every file leaves by Save a Copy.** The first 500 lines of a text file are shown the way a note is. Save a Copy writes the file back out, readable only by you. Nothing is opened in another app, since that would mean leaving a decrypted copy wherever that app kept it.
- **Files are in the encrypted backup.** Each one travels inside the archive, in base64 beside the name it had, and the archive's own instructions now say how to write one back out with `jq` and `base64` — no KeyVault needed. An older KeyVault restoring a new archive skips the files and says so.

**Fixed**
- **Restoring a backup no longer strips note categories, and backups now carry them.** Exports never recorded a note's category, and a restore rewrote every note it touched without one, so rehearsing the restore drill quietly un-filed your notes. Categories are now in the archive, and a restore keeps the category a note already has when the archive does not name one. Archives made with 1.8.1 or earlier contain no categories: restored onto a new Mac their notes come back uncategorised, and restored onto the Mac they came from they keep the categories they have.
