KeyVault

A key manager and a Keychain-backed store for secrets, with encrypted backup that any gpg can read.

Download GitHub

Managers and Stores

KeyVault does two different jobs behind one window, and the difference decides how careful you need to be.

SSH, GPG and Age are managed. The key material already exists — in ~/.ssh, in your GPG keyring, in the Age key files you point at under Settings. KeyVault finds it, shows it, and can generate more. It is never the only copy.

API Keys and Notes are stored. These live in the macOS Keychain because KeyVault put them there. For a Note, nothing else holds a copy — which is the whole reason the backup section below exists.

Getting Started

Open KeyVault and the sidebar lists what it found: SSH keys from ~/.ssh, GPG keys from your keyring, Age keys from the paths in Settings, plus anything you have stored.

Add something with the + under the list, the toolbar, or ⌘N for a note and ⇧⌘N for an API key.

Unlocking

If you have set a master passphrase, KeyVault asks for it at launch, and nothing stored is read until you give it. Not even the names — those are the part of a Keychain item that is never encrypted, so a locked window that listed them would be giving away most of what someone looking over your shoulder wanted.

The prompt can be cancelled. The window then sits locked, with an Unlock… button in the middle of it, so opening KeyVault by mistake costs a keystroke instead of a passphrase. ⇧⌘L locks and unlocks from the keyboard, and locking clears what was loaded rather than merely covering it.

KeyVault also shuts itself when you leave it alone — after 15 minutes by default, changed or turned off under Settings → Lock when idle. Time spent in another app counts, since walking away is the case it is for.

An idle lock reopens with Touch ID, and it is the only lock that does. A fingerprint is a yes-or-no answer rather than a secret to derive a key from, so opening a vault from cold with one would mean keeping the key on disk — which is the thing the encryption is there to avoid. An idle lock only hides a vault this run of the app already had open: the key stays in memory where it already was, and nothing new is written anywhere. Lock Vault Now and ⇧⌘L forget the key outright, and after those — as at every launch — only the passphrase opens the vault.

Notes

A note is a titled, multi-line secret that KeyVault owns outright — recovery codes, an account number, a licence key, the contents of a key file.

The editor is deliberately not masked. Notes are usually pasted in bulk, often straight from a file, and a masked single-line field mangles multi-line input while hiding the evidence that it did. You cannot proof-read what you cannot see, and for a value nothing else holds a copy of, proof-reading is the point.

Load from File… reads a file in verbatim. Nothing is trimmed — a trailing newline is part of some key formats, and quietly stripping it produces a value that looks right and does not work.

API Keys

Same storage, different question. An API key belongs to a service and fits on one line, so it gets a service field and a masked entry. Use a note instead when the value is long, multi-line, or came out of a file.

Reading a Secret

Select the item and the secret is there. Unlocking the vault was the deliberate act; a second click per note added friction with nothing behind it. Hide puts one away again for the moment someone is standing behind you, and everything stays hidden while the vault is locked.

Only one secret is in memory at a time — selecting anything else drops the last one.

Copy marks the clipboard as concealed, which tells clipboard managers not to archive it, and clears the clipboard after 45 seconds — but only if it still holds that secret, so it never wipes something you copied in the meantime.

Deleting

Deleting a note removes it from the Keychain immediately and permanently. There is no trash and no undo, which is why the confirmation says so plainly and why there is no minus button beside the list.

If you have not exported a backup, cancel and do that first.

Encrypted Export

Notes live in the macOS Keychain: encrypted at rest, tied to your login. That protects them from other people. It does not protect them from a dead Mac, and Keychain items do not leave the machine they were made on.

Backup & Restore — in the toolbar, or ⇧⌘B — writes every stored secret to one passphrase-encrypted archive. It is OpenPGP, AES-256, ASCII-armored.

Two properties are deliberate. It is plain text, so it survives a password manager field, an email to yourself, or a printer — none of which a binary blob does reliably. And it is readable without KeyVault:

gpg --decrypt keyvault-export.asc > vault.json

Any GnuPG, on any platform, opens it. Inside is a JSON document with each value in the clear, carrying its own decryption instructions. That is the exit: this app is not somewhere your secrets can get stuck.

The passphrase is stored nowhere and cannot be reset. Lose it and the archive is unreadable by you as well as by everyone else.

Restoring

Restore reads an archive and writes its contents back. It is keyed on each item's identifier, so it adds what is missing and updates what already exists rather than creating duplicates. Importing the same archive twice is harmless.

The Restore Drill

Because restore is idempotent, rehearsing it costs nothing. Do it.

Nothing should exist only in KeyVault until you have restored an archive somewhere else and read the value back. An untested backup is not a backup — it is an assumption, and the moment you discover it was wrong is the moment you needed it.

The check that matters is not that the file exists. It is that gpg --decrypt outside the app returns the value you put in, character for character.

SSH, GPG and Age

These are managed rather than stored. SSH keys load from ~/.ssh, GPG from the system keyring, and Age from the file paths listed under Settings.

They are not included in the encrypted export, because KeyVault is not their only home — they are files on disk and entries in a keyring, with their own backup story. Deleting an SSH key here deletes the file; deleting a GPG key removes it from your keyring.

How Storage Works

Stored items are kSecClassGenericPassword entries under the service io.github.sevmorris.KeyVault, and each is self-describing: the name, type and metadata live in the Keychain item's own attributes.

That matters more than it sounds. An earlier design kept the index in UserDefaults and only the payload in the Keychain, which meant losing that one file turned every secret into an anonymous blob keyed by an identifier nothing referenced any more. The data survived; the ability to find it did not. Items written under the old scheme are migrated automatically on first launch.

Requirements

  • macOS 15.0 or later
  • gnupg for export and import — brew install gnupg
  • ssh-keygen (ships with macOS) for SSH keys; gpg for GPG keys; age-keygen for Age

The app sandbox is disabled, because it shells out to those tools.
